# DNS and enforcement investigation — lgtm-ci #1203

This fixture-owned experiment runs from `diagnostic/1203-dns-enforcement`.
It replaces `egress.yml` on that branch only; fixture main, the existing egress
contract and the external canary remain unchanged. Dispatch the existing egress
workflow with this branch as its ref. The branch has no automatic triggers.

## What this tests

Record the runner's resolver topology and firewall state before and after the
exact deployed hardener. Passively capture DNS text during real Git checkout and
synthetic artifact upload/download. Then test one explicitly unallowed public
host, using an address resolved and recorded before the hardener starts. This
avoids its denied-domain DNS sinkhole, for which agent v0.17.0 deliberately
suppresses connection events. No endpoint or firewall permission is added.
A failed request counts as confirmed blocking only when the active agent
records a fresh local drop for the exact destination and curl process.
Missing evidence is unconfirmed and fails that step; it is not a security pass.

The helper is fetched as a SHA-pinned remote Node action during normal
Actions setup, before any step runs. Its first invocation uses a real action pre
hook ahead of the hardener pre hook.
It refuses a baseline if the agent is already active. Startup must acknowledge
a listening capture before hardener setup proceeds. This permits collection
before hardening and checkout without copied lgtm-ci tooling. Action
pre-download itself is unavoidable bootstrap and can affect resolver caches;
"before" means before the hardener, not a pristine boot-time capture.

Keep block policy, pins and endpoint permissions unchanged between baseline and
any later targeted correction. No audit mode, blanket IP allowance, resolver
service shutdown, arbitrary network changes, credentials or consumer workloads
are part of the baseline. The two jobs run serially, one amd64 and one ARM64,
with eight-minute job limits and no automatic retry. Regions are observed, not
selectable. Initial sampling is one dispatch. At most two additional sampling
dispatches may be used if no affected configuration was observed; this is not
permission to retry failing consumer CI or to call a passing region a fix.

## Interpretation and evidence

A complete success requires real checkout, artifact roundtrip, confirmed
negative-control blocking, artifact publication and successful terminal jobs,
including post steps. Observe the exact run attempt from outside the runner:
a `Complete job` log or our final marker alone is insufficient. Preserve API job
states, annotations and logs if reporting stalls. At the bounded job timeout,
record failure or unknown; never turn missing evidence into green.

Capture UTC times, workflow and helper commits, source/binary hashes, image,
region, architecture, resolver answers and corresponding application connections
and local drops. DNS and firewall snapshots are diagnostic observations, not
proof of vendor responsibility. A passing unaffected sample is inconclusive.
Compare a failing affected sample with successful controls and reproduce one
narrow remedy before considering shared rollout. Packet capture is finite and
filtered to infrastructure DNS text, with no pcap or HTTP payload. No raw
credentials, environment dumps or full agent configuration are collected.

A job-local request freezes coherent timestamped UTC DNS records (including
Linux cooked-v2 interface/direction headers) before active comparisons and
SHA256SUMS. The supervisor writes internal results only; the caller exclusively
publishes final artifact names once. A freeze timeout permanently marks that
attempt unconfirmed, even if a delayed internal acknowledgement arrives. Missing
capture startup/window health, relevant GitHub
queries/answers or agent observations makes overall completeness UNCONFIRMED,
even if network operations succeed. The pre-step order and collection lifetime
remain hosted observations to verify, not assumptions from local tests.
Freeze captured text before creating SHA256SUMS. Download logs, artifacts and
API receipts outside the runner; verify the artifacts' inner manifest. Preserve
failed runs rather than deleting or overwriting them. A reviewed, sanitized
release evidence bundle will carry its own checksum manifest bound to a signed
commit, because ordinary Actions artifacts expire (current fixture limit:
90 days). That records evidence integrity; it is not SLSA build provenance.

## Review and rollout

Each diagnostic correction and any shared fix requires a separate independent
Sol review of its exact source. Keep the original failure and all later review
findings in the evidence record. A supported, demonstrated remedy is proposed
in lgtm-ci with links to the fixture runs and lgtm-ci#1203, plus rollback and an
explicit removal condition if temporary. Validate its exact candidate SHA from
this external fixture, then one affected consumer before broader adoption.
The separate invalid TestPyPI endpoint issue #1206 is not fixed by this probe.

eastus2 (ARM64). Both inner artifact manifests were verified after download.
